# PRD — EZlook AI 자동 기술도식화 생성기 (AI Technical Flat Sketch Generator)

> 출처: [EZlook가 AI Tech Packs 같은 기능을 보유하려면 — 전략 요약](https://app.notion.com/p/3d0f14bb4d888124839fddd126b55e2e) (2026-09-05 기준)
> 이 문서는 위 기획 문서의 "1단계 AI 기술 도식화 생성기" + "1단계 AI 바이브 코딩" 섹션을 실행 가능한 PRD로 정리한 것이다.

## 1. 프로젝트 목적

EZlook의 기존 강점인 **"상품 이미지 1장 → 모델컷/룩북/영상 생성"** 흐름을 생산 단계까지 확장하기 위해, 의류 상품 사진을 기반으로 **공장용 기술도식화(technical flat sketch)**를 자동 생성하는 웹 기능을 개발한다.

1차 목표:
- flat-lay 상품 사진 1장을 업로드하면
- AI가 의류 카테고리를 인식하고
- 앞면 기준의 기술도식화(flat sketch)를 생성하며
- 필요 시 뒷면 도식화도 생성하고
- 결과물을 **SVG 및 PNG**로 다운로드 가능하게 한다

장기적으로는 작업지시서(Tech Pack), POM(측정 포인트), BOM(자재명세서), QC, PDF/Excel export, 공장 공유 기능으로 확장한다.

## 2. 제품 정의

> **"의류 사진 1장으로 생산용 기술도식화와 작업지시서 초안을 만들고, 브랜드가 수정·검수한 뒤 공장에 전달할 수 있게 하는 웹 기반 협업 툴"**

경쟁사([AI Tech Packs](https://aitechpacks.com/))도 생성 결과를 바로 공장에 보내라고 하지 않고 **editable draft → review → approval → export/share** 흐름을 강조한다. 즉 "AI가 100% 맞게 만들어주는 마법"보다 **사람이 빠르게 검수할 수 있는 반자동 시스템**이 제품 적합성이 높다.

## 3. 제품 포지셔닝 (개발 원칙)

1. **예쁜 스케치 생성**보다 **구조 정확도**를 우선한다.
2. 결과물은 디자이너가 후편집 가능한 **생산용 플랫**이어야 한다.
3. 완전 자동보다 **80점 초안 + 사람 수정 가능한 워크플로우**를 지향한다.
4. 처음부터 전체 Tech Pack을 만들지 말고, **기술도식화 생성기 단독 MVP**부터 만든다.
5. **생성형-only 방식 금지** — 사진을 바로 스케치 스타일로 변환하는 방식만으로는 좌우 대칭·절개선 정리·포켓 위치 일관성·소매/몸판 비례가 흔들릴 가능성이 높다. 반드시 **비전 분석 + 카테고리 분류 + 구조 요소 추출 + 템플릿 매핑 + 벡터화**의 하이브리드 구조로 설계한다.

## 4. MVP 범위

### 반드시 포함
1. 사용자 로그인 없이도 테스트 가능한 업로드 화면
2. 상품 사진 업로드
3. 업로드 이미지 품질 검사
4. 의류 카테고리 분류
5. 앞면 기술도식화 생성
6. 옵션 기반 뒷면 생성
7. 결과 미리보기
8. 간단 편집 기능 (구조 속성 기반 재렌더링 — 픽셀 편집 아님)
9. SVG 다운로드
10. PNG 다운로드
11. 생성 이력 저장
12. 관리자 페이지에서 실패 케이스 확인

### MVP에서 제외 (2차 이후)
1. 전체 Tech Pack 자동 생성
2. Excel/PDF export
3. BOM/POM 편집기
4. 공장 공유 링크
5. 다국어 번역
6. Illustrator 플러그인
7. Batch generation
8. 컬렉션 관리

## 5. 1차 지원 의류 카테고리

**반팔 티셔츠 · 맨투맨 · 후디** 3개만 먼저 지원한다.

이유: 구조가 비교적 표준화됨 / 데이터셋 구축이 쉬움 / 수요가 많음 / 템플릿 기반 정확도 확보에 유리함.

2차 확장: 셔츠/블라우스 → 팬츠/데님 → 아우터 → 원피스

## 6. 입력 조건

업로드 가능 파일: JPG, PNG, WEBP · 최대 10MB · 최소 해상도 1200px 이상 권장

권장 조건 (업로드 전처리 화면에서 검사):
- flat-lay 사진, 배경과 의류의 대비가 높을 것
- 의류 전체가 프레임 안에 들어올 것
- 그림자·반사가 적을 것
- 주름이 심하지 않을 것
- 정면/후면 여부, 카테고리 자동 판별

## 7. 출력 요구사항

- 필수 출력: PNG, SVG
- 품질 기준: 좌우 대칭 자연스러움 / 외곽선 단순·깔끔 / 봉제선·절개선·포켓·후드·지퍼 등 주요 디테일 보존 / 배경 잔여물 없음 / 편집 가능한 구조 / SVG path 정리 상태 양호
- 스타일: black line on white background 기본, clean technical drawing style, shading·texture 최소화, decorative sketch 느낌 금지

## 8. MVP 편집 기능 (구조 속성 기반)

pocket on/off · hood on/off · zipper on/off · sleeve length toggle · hem rib toggle · neckline type select · seam line visibility toggle · stroke thickness adjust · front/back switch · regenerate

## 9. 사용자 플로우

**플로우 1 — 기본 생성**
업로드 페이지 진입 → 사진 업로드 → 품질 검사 → 카테고리 자동 인식 → 사용자 확인/수정 → 앞면 생성 → 뒷면 생성 여부 선택 → 결과 미리보기 → 간단 수정 → SVG/PNG 다운로드

**플로우 2 — 재생성**
결과 확인 → 디테일 옵션 변경 → regenerate → 결과 비교

**플로우 3 — 관리자 검수**
실패 케이스 목록 확인 → 원본/결과 비교 → 카테고리 오분류·디테일 누락 태깅 → 데이터셋 개선 대상으로 저장

## 10. 품질 기준

### MVP 성공 기준
1. 티셔츠/맨투맨/후디 3개 카테고리 정확 분류
2. 앞면 플랫 생성 성공률 90% 이상
3. SVG 다운로드 성공률 95% 이상
4. 디자이너가 수동 수정 가능한 수준의 결과
5. 포켓/후드/지퍼 등 핵심 디테일 누락률 최소화
6. 평균 처리 시간 60초 이내

### 정성 기준
- 공장 전달용 초안으로 사용할 수 있어야 함
- "예쁘다"보다 "읽힌다"가 중요
- 지나친 아트 스타일·음영·장식성 금지

## 11. 개발 우선순위 (Phase)

- **Phase 1**: 업로드 · 전처리 · 카테고리 분류 · 앞면 플랫 생성 · PNG/SVG export
- **Phase 2**: 뒷면 플랫 생성 · 디테일 옵션 편집 · regenerate · 히스토리 저장
- **Phase 3**: 관리자 페이지 · 피드백 저장 · 실패 케이스 분석 · 품질 대시보드
- **Phase 4**: POM 연결 준비 · structured JSON 고도화 · Tech Pack 확장 설계

## 12. 개발 시 주의사항

1. 처음부터 모든 카테고리 지원 금지
2. 처음부터 전체 Tech Pack 생성 금지
3. 결과를 이미지 하나로만 저장하지 말고 **구조화 JSON을 반드시 남길 것**
4. 편집 불가능한 결과물 금지
5. 생성형 모델에만 의존하지 말 것
6. 운영자가 실패 케이스를 수집·개선할 수 있는 구조를 먼저 만들 것

## 13. 데이터 전략 (장기)

이 기능은 "어떤 모델을 쓰느냐"보다 **학습/평가용 데이터셋**이 중요하다. 최소 필요 데이터: 상품 사진, 정답 플랫(front/back), 카테고리 라벨, 디테일 라벨(카라·포켓·지퍼·절개·시보리 등), 대칭 기준선, 수정 이력. 실무적으로 처음부터 1만 장이 필요하지 않다 — **카테고리 3개 × 각 200~500개 수준의 고품질 정답셋**이 더 중요하다.

## 14. 비즈니스 전략 메모

현재 공개 정보로는 AI Tech Packs의 공개 API가 확인되지 않아, 외부 API 의존 전략은 불안정하다. 추천 전략은 **Hybrid**: 초기에는 자체 구축을 기본으로 하되, 템플릿 자문·생산 문서 구조 검수·도메인 전문가 네트워크 같은 비기술 영역은 외부 파트너를 활용한다.

(단, 이 세션에서 별도로 조사한 결과 aitechpacks.com 외에도 LOOK AI, StyleAI, Fashion Diffusion, The New Black 등 유사 서비스가 존재하며 일부는 API/export 연동을 표방한다 — 자체 개발 착수 전 이들과의 제휴/재판매 가능성을 먼저 타진해보는 것을 권장한다.)
